## 一、项目定位（1 句话）

**全流程负责的图像操作 Agent 专家系统** —— 接收用户「图片 + 自然语言需求 + 参考信息」，输出「满足要求的高质量图像结果 + 评审报告 + 可追溯的操作链路」。

---

## 二、核心设计决策（Top 10）

| 决策 | 选择 | 理由 |
|-----|------|------|
| **评估对象** | 全流程负责 | 从需求理解→任务拆解→执行→评估→迭代闭环 |
| **评估模式** | 混合模式 | 规则检查（客观）+ LLM 评估（主观）+ 用户确认 |
| **专家生成** | 预设 + 动态 | 静态专家按需加载 + 动态专家 LLM 生成 |
| **记忆体系** | 三层架构 | 任务记忆→会话记忆→持久记忆（共享黑板） |
| **部署模式** | 本地运行 + 云端 API | 专家系统本地，大模型调用走云端 |
| **API 限流** | Token 桶 + 指数退避 | 防止并发请求触发 Rate Limit |
| **黑板控制** | Append-only | 专家只能追加事件，不能修改历史 |
| **模型路由** | 智能动态选择 | 根据任务类型选择最合适模型 |
| **置信度阈值** | 0.5/0.3 两级干预 | 低于 0.5 通知 PM，低于 0.3 自动重新分配 |
| **Auto-Fallback** | 合规违规自动补救 | 最多 3 次修复尝试，失败后驳回 |

## 三、专家架构（10 位静态专家）

### 常驻专家（4 位）
1. **项目经理** - 任务拆解、进度把控、死锁打断
2. **合规与法律专家** - 一票否决权，准入 + 交付审查
3. **视觉专家** - 核心执行与审核，可分裂为执行/审核实例
4. **知识管理员** - 共享黑板管理、记忆压缩与索引

### 按需加载专家（6 位）
5. **资深 HR 专家** - 能力缺口识别、动态专家"招聘"
6. **Prompt 工程师** - 模糊需求转化、跨模型适配
7. **摄影师** - 光线/构图分析、真实感评估
8. **图像编辑师** - 复杂编辑拆解、mask 生成
9. **室内设计师** - 空间布局、风格搭配
10. **陈列设计师** - 商品展示、视觉营销

## 四、工作流转（7 步）

```
1. [一票否决] 合规审查用户需求 → 不通过则驳回
2. 任务初始化 → PM+ 视觉专家+HR 决定引入哪些专家 → 可行性打分
3. 专家接单 → 自评置信度 (Confidence Score)
4. 阵营分裂 → 执行组 vs 审核组 → 依赖串行/无依赖并行
5. 黑板讨论 → 加权互评 → 评分 × (可行性 × 置信度)
6. [强制打断] 讨论超阈值 → PM 组织投票收敛
7. [一票否决] 最终合规审查 → 交付 + 操作链路记录
```

## 五、记忆空间设计

| 层次 | 范围 | 内容 | 保留策略 |
|-----|------|------|---------|
| **任务记忆** | 单任务 | 中间状态、临时决策 | 任务结束清除 |
| **会话记忆** | 单 session | 专家交互记录 | Session 结束清除 |
| **持久记忆** | 全局共享 | 任务历史、用户偏好、领域知识、专家索引 | 压缩后永久保存 |

**共享黑板**：所有专家可读写，知识管理员监控并压缩

**专家索引库**：记录能力标签、领域标签、历史表现，支持检索

## 六、技术架构

**架构分层**:
```
专家应用层 → 请求调度层 (限流/路由/重试) → 模型适配层 → 云端模型层
```

**关键技术点**:
- **大模型层**: Azure OpenAI + Google VertexAI（多模型消除偏见）
- **模型白名单**:
  - 允许：GPT-4o 系列、Gemini 2.5/3.0 Pro/Flash、Imagen-3
  - 禁止：GPT-4 及更早版本、Gemini 2.5 之前版本
- **限流重试**: Token 桶限流 + 指数退避重试
- **黑板控制**: Append-only Event Sourcing + 知识管理员定期压缩
- **并发层**: Python 多线程/多进程混合
- **存储层**: 本地文件系统 + SQLite/JSON + 向量数据库（可选）
- **媒体内核**: VertexAI 调用 Gemini/Imagen 生图/生视频模型
- **Auto-Fallback**: 合规违规自动补救 (最多 3 次) + 驳回报告

---

## 七、关键设计亮点

1. **可行性打分 + 置信度自签** - 任务分配时评估专家能力，专家接单后自评，加权计入决策
2. **执行/审核分裂** - 视觉专家或领域专家组分裂为两个阵营，形成内部制衡
3. **操作链路可追溯** - 记录「删除 A、调亮 B、添加 C...」，用户可 fork 继续处理
4. **动态专家注册** - 新专家被索引到专家库，系统能力持续进化
5. **混合并发** - 有依赖串行，无依赖多线程并行，自由讨论后加权互评
6. **API 限流保护** - Token 桶限流 + 指数退避重试，防止并发压垮 API
7. **黑板 Append-only** - 专家只能追加事件，知识管理员定期压缩摘要
8. **模型智能路由** - 根据任务类型动态选择模型，禁止使用过时模型
9. **置信度干预** - 低于 0.5 通知 PM，低于 0.3 自动重新分配
10. **Auto-Fallback** - 合规违规自动尝试修复（最多 3 次），失败后附详细报告驳回
